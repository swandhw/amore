  3. 지적사항 종합

  [A] SearchParams 필드명 — combo1→codeType 리네이밍 필요                                                                            
  ┌────────┬───────────┬──────────────────────────────────┐
  │ 생성물         │  정답지              │            XFDL 근거                                               │
  ├────────┼───────────┼──────────────────────────────────┤
  │ combo1         │ codeType             │ caption4 Static text="코드타입"                                    │
  ├────────┼───────────┼──────────────────────────────────┤
  │ combo2         │ useStatus            │ caption50 Static text="사용유무"                                   │
  └────────┴───────────┴──────────────────────────────────┘
  파이프라인이 combo id를 그대로 사용. Static label 매핑으로 개선 가능.

  [B] DsCombo2 불필요 생성

  ds_combo2와 ds_SearchListResult14_Row는 동일 코드(014) 조회. XFDL 스크립트 근거:
  // xfdl 218줄: ds_combo2용
  submitData = "CODE_TYPE=014"+this.gfn_GetTranInfo("PLANT|LANG_TYPE");
  정답지처럼 ds_SearchListResult14_Row 하나로 통합이 적절.

  [C] API 샘플 데이터 품질

  XFDL Dataset ds_SearchListResult14_Row에 초기 rows(Yes/No)가 있는 경우 정확히 반영됨. ds_combo1, ds_SearchListResult535_Row는 초기
  rows 없음(서버 조회 후 채워짐). 정답지의 업무 데이터는 수동 입력 영역.

  [D] View title 텍스트

  XFDL titleName.text="조회조건" 반영 결과. 정답지의 "불량코드등록"은 Form.titletext 또는 화면명에서 파생하는 방안 필요. 영향:
  060_view_page_assembler

  [E] 검색 필터 초기값

  XFDL fn_CallBack에서 combo2.set_value(application.C_USEY) 로 기본값 설정. 스크립트 분석 자동화 범위 확장 시 대응 가능.

  [F] 사용유무 combo 데이터소스

  XFDL상 combo2.innerdataset="ds_combo2" 이므로 파이프라인 출력은 정확. 정답지는 동일 데이터를 가진 ds_SearchListResult14_Row로 통합
   최적화.
