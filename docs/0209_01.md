# 0209 변경사항 - ASIS 근거 분류

> 020~060 py 수정 시, ASIS 소스에서 추출 가능한 항목과 새로 추가해야 하는 항목을 분리

---

## A. ASIS(xfdl/xml/java)에 근거가 있는 변경

### A-1. align 속성 (xfdl body cell style에 존재)

xfdl에 `style="align:center middle;"` 등의 정렬 정보가 있음. **단, 0209와 실제 값이 다름:**

| 컬럼 | xfdl style | 0209 align | 일치 |
|------|-----------|------------|:----:|
| 제품구분 (PRD_CI) | (없음, 기본값) | `center` | X |
| 불량코드구분 (BAD_CI) | `align:center middle` | `left` | X |
| 불량코드 (BAD_CODE) | (없음) | `left` | X |
| 불량코드명 (BAD_CODE_NAME) | `align:left middle` | `right` | X |
| 사용유무 (CUD_CI) | `align:center middle` | `right` | X |
| 비고 (REMARK) | `align:left middle` | `center` | X |

**판단:** xfdl에서 align 값을 읽을 수는 있지만, 0209에서 의도적으로 다르게 설계한 것으로 보임.
py 스크립트에서 xfdl align을 추출하되, 0209 팀이 수동으로 변경할 수 있는 구조가 필요.

### A-2. isRequired 속성 (xfdl 저장 시 NULL 체크)

xfdl `button3_onclick` (저장)에서 PK NULL 체크 (line 336~351):
```javascript
var checkItem = [PRD_CI, BAD_CI, BAD_CODE, BAD_CODE_NAME];
// PK 확인 (NULL 체크)
```

| 컬럼 | xfdl NULL 체크 | 0209 isRequired | 일치 |
|------|:-------------:|:--------------:|:----:|
| productCategory (PRD_CI) | O | `true` | O |
| badCodeCategory (BAD_CI) | O | `true` | O |
| badCode (BAD_CODE) | O | `true` | O |
| badCodeName (BAD_CODE_NAME) | O | (없음) | **X** |

**판단:** xfdl에서 null 체크 대상 컬럼을 추출하여 isRequired 매핑 가능. 단, 0209에서 BAD_CODE_NAME은 의도적으로 제외한 것으로 보임.

### A-3. 권한 체크 - usePageCrudAuth

xfdl line 192: `this.gfn_CommL3AuthChk(true,"1");`
→ 0209: `usePageCrudAuth(PAGE_NAME)` + `commonButtonProps.can`

**판단:** ASIS에 근거 있음. py 스크립트에서 `gfn_CommL3AuthChk` 호출 존재 여부 감지 → `usePageCrudAuth` 생성 가능.

### A-4. CloseGuard (enableCloseGuard)

xfdl:
- line 157: `this.value_change_flag = false;`
- line 322: `this.value_change_flag = true;` (등록 시)
- line 426: `this.value_change_flag = true;` (컬럼 변경 시)
- line 387: `this.gfn_Button5(this.value_change_flag);` (종료 시 확인)

→ 0209: `enableCloseGuard: true`

**판단:** ASIS에 `value_change_flag` + `gfn_Button5` 패턴이 있으면 `enableCloseGuard: true` 생성 가능.

### A-5. onBeforeCreate - 현재 행 값 복사 (부분)

xfdl `button2_onclick` (등록) line 294~323:
```javascript
// 현재 행이 있으면 PRD_CI, BAD_CI 복사
this.ds_datagrid1.setColumn(addedRow, "PRD_CI", this.ds_datagrid1.getColumn(row, "PRD_CI"));
this.ds_datagrid1.setColumn(addedRow, "BAD_CI", this.ds_datagrid1.getColumn(row, "BAD_CI"));
// CUD_TYPE=C, CUD_CI=Y 설정
this.ds_datagrid1.setColumn(addedRow, "CUD_TYPE", application.C_CUDINSERT);
this.ds_datagrid1.setColumn(addedRow, "CUD_CI", application.C_USEY);
// 공장별 PRD_CI 기본값 설정
if(this.plant == "1111") { ... "MC" }
```

→ 0209 `onBeforeCreate`:
- `badCodeCategory` 복사 (= BAD_CI 복사) **ASIS 근거 O**
- useStatus: 'Y' (= CUD_CI=Y) **ASIS 근거 O** (createBadCodeRow에서 처리)
- 시 인용구 remark 설정 **ASIS 근거 X** (테스트/데모 목적)
- 공장별 PRD_CI 분기 **ASIS에는 있으나 0209에서 미적용**

**판단:** 부분적 근거. 복사 대상 컬럼 목록은 xfdl button2_onclick에서 추출 가능.

### A-6. save - 서버 호출 구조

xfdl line 360~371:
```javascript
this.gfn_Transaction(this, "save", "multi", "D_MMASM_BAD_CODE-service",
  "ds_datagrid1=ds_datagrid1:A", "", submitData, "fn_CallBack", ...);
```

→ 0209: `saveBadCodeRegisters(dsName, payload)` + `apiPost('/badCodeRegisters', dsName, payload)`

**판단:**
- 서비스명 (`D_MMASM_BAD_CODE-service`) → API 경로 매핑 가능
- 데이터셋명 (`ds_datagrid1`) → `dsName` 파라미터로 전달 가능
- `:A` (All rows) → 전체 행 전달 방식

### A-7. 저장 시 필수값 검증 (onValidateIntegrity 부분)

xfdl line 330~351: 저장 전 PK 컬럼 NULL 체크
→ 0209: `isRequired`로 그리드 레벨 처리 (A-2와 연결)

**판단:** xfdl의 null 체크는 `isRequired`로 대체. 단, 0209의 중복 체크(duplicate)는 ASIS에 없음 (B-4 참조).

## B. ASIS에 근거가 없는 변경 (새로운 아키텍처/패턴)

### B-1. `_op` 필드 제거 (Row 타입에서 CUD 상태 분리)

- ASIS에 CUD_TYPE 컬럼은 있으나, 이를 Row 타입에서 제거하고 useGrid 내부에서 관리하는 것은 **프레임워크 설계 결정**
- py 스크립트 영향: 040 (Types) - `_op` 필드 생성하지 않도록 변경

### B-2. mocks.ts (MSW 기반 Mock 서비스)

- ASIS에 해당 개념 없음. 완전히 새로운 **테스트 인프라**
- `msw` 라이브러리를 사용한 API 엔드포인트 목업
- 서버-클라이언트 필드명 매핑 관계 정의 (`prdCi` ↔ `productCategory` 등)
- py 스크립트 영향: 050 (API) - mocks.ts 생성 로직 추가

### B-3. CommonButtonsProps 패턴 (View 인터페이스 표준화)

- ASIS에 없는 React 아키텍처 패턴
- 개별 핸들러 props → `CommonButtonsProps` 객체 하나로 통합
- `can` 속성으로 권한 기반 버튼 제어
- py 스크립트 영향: 060 (View) - Props 구조 변경, spread 패턴 적용

### B-4. onValidateRowDelete (사용중 삭제 차단)

- ASIS xfdl에 삭제 전 검증 로직 없음 (CUD_TYPE='D'로 마킹만 함)
- `useStatus === 'Y'`이면 삭제 차단은 **새로운 비즈니스 로직**
- py 스크립트 영향: 060 (Page) - 화면별 커스텀 영역, 자동생성 어려움

### B-5. onValidateIntegrity (중복 조합 체크)

- ASIS xfdl 저장 시에는 NULL 체크만 존재
- `badCodeCategory + badCode` 중복 체크는 **새로운 비즈니스 로직**
- py 스크립트 영향: 060 (Page) - 화면별 커스텀 영역, 자동생성 어려움

### B-6. onBeforeCreate - 시 인용구 remark 설정

- 테스트/데모 목적의 코드. ASIS에 해당 없음
- py 스크립트 영향: 없음 (자동생성 불필요)

### B-7. enableSearchGuard (검색 시 미저장 경고)

- ASIS에서 검색 시 별도 확인 없이 바로 실행 (`value_change_flag = false`)
- 검색 전 미저장 변경 경고는 **새로운 UX 패턴**
- py 스크립트 영향: 060 (Page) - enableCloseGuard와 함께 옵션으로 생성

### B-8. FlexGrid columns prop 제거

- ASIS 개념과 무관. useGrid가 initialized 콜백에서 내부적으로 컬럼 설정
- py 스크립트 영향: 060 (View) - FlexGrid에서 columns prop 제거

### B-9. handleSearchWithFilters return 변경

- `handleSearch(params)` → `return handleSearch(params)` (Promise 반환)
- useGrid 내부 SearchGuard와 연동하기 위한 프레임워크 요구사항
- py 스크립트 영향: 060 (Page) - return 추가

### B-10. View import 축소 (BadCodeRegisterRow, GridColumnDef 제거)

- View가 더 이상 Row 타입과 컬럼 정의를 알 필요 없음
- py 스크립트 영향: 060 (View) - import 구조 변경

## C. ASIS 근거는 있으나 0209에서 다르게 표현된 항목 (3건)

> py 스크립트에서 xfdl 기준으로 자동 추출하면 0209 결과와 불일치 발생. 수동 조정 필요 영역.

### C-1. align - 전체 컬럼 불일치

| 컬럼 | xfdl | 0209 |
|------|------|------|
| 제품구분 (PRD_CI) | (없음/기본) | `center` |
| 불량코드구분 (BAD_CI) | `center` | `left` |
| 불량코드 (BAD_CODE) | (없음/기본) | `left` |
| 불량코드명 (BAD_CODE_NAME) | `left` | `right` |
| 사용유무 (CUD_CI) | `center` | `right` |
| 비고 (REMARK) | `left` | `center` |

6개 컬럼 모두 불일치. xfdl에서 추출해도 0209 결과와 맞지 않음.

### C-2. isRequired - BAD_CODE_NAME 불일치

| 컬럼 | xfdl NULL 체크 | 0209 isRequired |
|------|:-------------:|:--------------:|
| PRD_CI | O | O |
| BAD_CI | O | O |
| BAD_CODE | O | O |
| **BAD_CODE_NAME** | **O** | **(없음)** |

xfdl에서는 4개 컬럼 모두 필수인데, 0209에서는 BAD_CODE_NAME만 빠짐.

### C-3. onBeforeCreate - 복사 대상 컬럼 불일치

| 항목 | xfdl button2_onclick | 0209 onBeforeCreate |
|------|---------------------|---------------------|
| PRD_CI 복사 | **O** | **X** (미적용) |
| BAD_CI 복사 | O | O (`badCodeCategory`) |
| 공장별 PRD_CI 기본값 | **O** (1111->MC, 1112/5220->GT, 1113->HC) | **X** (미적용) |

xfdl은 PRD_CI와 BAD_CI 둘 다 복사 + 공장 분기가 있지만, 0209는 BAD_CI만 복사.
