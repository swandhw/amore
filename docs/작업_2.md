# AI UI 변환 규칙 v2.0

> 정답 파일(`badCodeRegister/`)을 기반으로 역산한 전체 변환 규칙.
> `D_MMASM_BAD_CODE`를 `BAD_CODE_REGISTER`로 가정한 정답을 기준으로 작성.

---

## 1. 생성 파일 목록

화면 1개는 다음 파일로 분해된다.

```
{화면명}/                              ← camelCase 폴더
├── {화면명}.META.json                 ← PascalCase
├── {화면명}View.tsx                   ← PascalCase + View
├── {화면명}Page.tsx                   ← PascalCase + Page
├── hooks/
│   ├── useCreate{화면명}Row.ts        ← PascalCase
│   └── useCreateGridColumn.ts
├── api/
│   └── {screenName}Api.ts             ← camelCase + Api
└── types/
    └── {화면명}Types.ts               ← PascalCase + Types
```

### 명명 규칙

| 대상 | 규칙 | 예시 (BAD_CODE_REGISTER) |
|------|------|--------------------------|
| 폴더명 | camelCase | `badCodeRegister/` |
| 컴포넌트명 (화면명) | PascalCase | `BadCodeRegister` |
| Page 파일 | PascalCase + Page | `BadCodeRegisterPage.tsx` |
| View 파일 | PascalCase + View | `BadCodeRegisterView.tsx` |
| Types 파일 | PascalCase + Types | `types/BadCodeRegisterTypes.ts` |
| Row Hook 파일 | useCreate + PascalCase + Row | `hooks/useCreateBadCodeRow.ts` (화면명에서 적절히 축약 가능) |
| Column Hook 파일 | 고정 | `hooks/useCreateGridColumn.ts` |
| API 파일 | camelCase + Api | `api/badCodeRegisterApi.ts` |

## 2. 필드명 변환 규칙

SNAKE_CASE → camelCase 변환.

| 원본 | 변환 |
|------|------|
| `PRD_CI` | `prdCi` |
| `BAD_CI` | `badCi` |
| `BAD_CODE` | `badCode` |
| `BAD_CODE_NAME` | `badCodeName` |
| `CUD_CI` | `cudCi` |
| `CODE_KOR_NAME` | `codeKorName` |
| `CODE_KOR_NAME_RE` | `codeKorNameRe` |
| `COMM_CODE` | `commCode` |

> **참고**: 정답에서는 의미있는 이름 (`productCategory`, `useStatus` 등)을 사용하나,
> 이는 사람이 매핑 테이블을 제공해야 하는 영역이다.
> 자동 변환에서는 기계적 camelCase를 사용하고, 이후 사람이 보정한다.

## 3. Types 파일 규칙

파일: `types/{화면명}Types.ts`

### 3.1 메인 Row 타입

```ts
export type {화면명}Row = {
  _op?: 'C' | 'U' | 'D' | '';    // 행 상태 추적 (필수 - 모든 Row에 포함)
  prdCi: string;                   // 그리드 바인딩 컬럼 (camelCase)
  badCi: string;
  badCode: string;
  badCodeName: string;
  cudCi: string;
  remark: string;
};
```

**규칙:**
- 그리드에 바인딩되는 메인 데이터셋 → `{화면명}Row`
- **`_op` 필드 필수**: 모든 Row 타입에 `_op?: 'C' | 'U' | 'D' | ''` 추가 (행의 CUD 상태 추적)
- ds_datagrid1 → `{화면명}Row`
- 필드명은 바인딩 컬럼의 camelCase 변환

### 3.2 SearchParams 타입

```ts
export type {화면명}SearchParams = {
  codeType?: string | null;      // 조회조건 필드 (Combo 기반)
  useStatus?: string | null;
};
```

**규칙:**
- 조회조건(Combo)이 있는 화면에서 생성
- 각 조회조건 Combo의 ID를 camelCase로 변환하여 필드 생성
- 모든 필드는 `?: string | null` (optional, nullable)

### 3.3 보조 Dataset 타입

```ts
export type DsCombo1 = {
  codeKorNameRe: string;
  commCode: string;
};

export type DsSearchListResult14Row = {
  codeKorName: string;
  commCode: string;
};

export type DsSearchListResult535Row = {
  codeKorName: string;
  commCode: string;
};
```

**규칙:**
- 콤보/조회조건용 Dataset은 원본 ID 기반 PascalCase
- `ds_combo1` → `DsCombo1`
- `ds_SearchListResult535_Row` → `DsSearchListResult535Row`

**규칙:**

**그리드 컬럼 변환 규칙:**

| META.json 원본 | 변환 대상 | 규칙 |
|----------------|-----------|------|
| `columns[].id` (한글 헤더) | `header` | 그대로 사용 |
| `columns[].binding` | `binding` | camelCase 변환 |
| `columns[].size` | `width` | `'*'` 사용 (고정 픽셀 대신) |
| - | `dataType` | `'String'` (항상 포함) |
| `edittype: "combo"` | `dataMap` | `createDataMap(데이터셋, valueCol, textCol)` |
| `combodataset` | `createDataMap` 1번째 인자 | Dataset 변수명 (camelCase) |
| `combocodecol` | `createDataMap` 2번째 인자 | camelCase 변환 |
| `combodatacol` | `createDataMap` 3번째 인자 | camelCase 변환 |

**함수 파라미터 규칙:**
- DataMap을 사용하는 컬럼이 있으면, 해당 Dataset을 파라미터로 받음
- 파라미터명: `ds` prefix 제거 후 camelCase (예: `ds_combo1` → `dsCombo1`)
- 파라미터 타입 정의는 인라인 객체 타입

**헤더 트리 규칙:**
- 변수명: `{SCREEN_UPPER_SNAKE}_HEADER_TREE` (대문자 SNAKE_CASE)
- 단일 컬럼: `createLeafNode(id, label, binding)`
- 그룹 컬럼 (head_rowspan > 1인 컬럼 그룹): `createGroupNode(id, label, children[])`
- leaf의 id와 binding은 camelCase 바인딩명과 동일

### 5.3 메인 데이터 조회

```ts
export const fetch{화면명}s = async (params?: {화면명}SearchParams) => {
  const codeType = normalizeFilterValue(params?.codeType);
  const useStatus = normalizeFilterValue(params?.useStatus);

  const filtered = {SCREEN_UPPER}_DATA.filter((row) => {
    if (codeType && row.badCi !== codeType) return false;
    if (useStatus && row.cudCi !== useStatus) return false;
    return true;
  });

  const response: ApiResponse<{화면명}Row[]> = {
    result: 'true',
    message: '',
    responseBody: filtered
  };
  return Promise.resolve(response);
};
```

- `ViewFill` 레이아웃 컴포넌트 사용
- `CommonButtons` 공통 버튼 컴포넌트 사용

### 6.2 Props 타입

```tsx
export type {화면명}ViewProps = {
  t: (key: string) => string;                       // i18n 번역 함수
  gridHeaderDefinition: GridColumnDef<{화면명}Row>[];  // 그리드 컬럼 정의

**규칙:**
- `t`: i18n 번역 함수 (Page에서 전달)
- `gridHeaderDefinition`: 그리드 컬럼 (Page에서 useMemo로 생성하여 전달)
- `searchSection`: 조회조건 ReactNode (Page에서 `SearchConditionFields` 렌더링하여 전달)
- 핸들러: `onSearch`, `onCreate`, `onDelete`, `onCommit`, `onExcel`, `onGridInitialized`
- **Dataset props 없음**: View는 combo 데이터를 직접 받지 않는다 (searchSection으로 주입)

  // ── 그리드 컬럼 정의 (useMemo - combo 데이터 변경 시 재생성) ──
  const GRID_COLUMNS = useMemo(() => (
    create{gridId}ColumnDefinition({
      dsSearchListResult535Row,
      dsSearchlistresult14Row: dsSearchListResult14Row,
      dsCombo1,
    })
  ), [dsSearchListResult535Row, dsSearchListResult14Row, dsCombo1]);

  // ── useGrid 훅 (CRUD 핸들러) ──
  const {
    handleSearch,
    handleCreate,
    handleDelete,
    handleCommit,
    handleExcel,
    handleGridInitialized: handleGridInitializedBase,
    isDirty,
    hasChanges,
  } = useGrid(
    create{화면명}Row,
    fetch{화면명}s,
    save{화면명}s,
  );

  // ── 닫기 보호 (미저장 변경사항) ──
  const closeGuard = useCloseGuardContext();
  const closeGuardTabId = useCloseGuardTabId();

  useCloseGuard({
    isDirty,
    hasChanges,
  });

  // ── 조회 + 필터 래핑 ──
  const handleSearchWithFilters = useCallback(() => {
    const params: {화면명}SearchParams = {
      codeType: typeof searchFilters.codeType === 'string' ? searchFilters.codeType : null,
      useStatus: typeof searchFilters.useStatus === 'string' ? searchFilters.useStatus : null,
    };
    handleSearch(params);
  }, [handleSearch, searchFilters]);

  // ── 조회 + 닫기 보호 래핑 ──
  const handleSearchWithGuard = useCallback(() => {
    const runSearch = () => {
      handleSearchWithFilters();
    };

    if (!closeGuard || !closeGuardTabId) {
      runSearch();
      return;
    }

    closeGuard.attemptSearch(closeGuardTabId, runSearch);
  }, [closeGuard, closeGuardTabId, handleSearchWithFilters]);

  // ── Grid 초기화 + 헤더 트리 드래그 ──
  const handleGridInitialized = useCallback((grid: FlexGrid) => {
    handleGridInitializedBase(grid);
    attachHeaderTreeDrag(grid, {
      tree: {SCREEN_UPPER}_HEADER_TREE,
    });
  }, [handleGridInitializedBase]);

  // ── JSX ──
  return (
    <{화면명}View
      t={i18n.t}
      gridHeaderDefinition={GRID_COLUMNS}
      searchSection={(
        isSearchComboReady ? <SearchConditionFields
          fields={searchFields}
          values={searchFilters}
          onValuesChange={setSearchFilters}
        /> : '로딩중...'
      )}
      onSearch={handleSearchWithGuard}
      onCreate={handleCreate}
      onDelete={handleDelete}
      onCommit={handleCommit}
      onExcel={handleExcel}
      onGridInitialized={handleGridInitialized}
    />
  );
}
```

## 8. 조회조건 (Search Condition) 규칙

### 8.1 SearchConditionFieldConfig

META.json의 Combos 정보를 기반으로 생성:

| META.json Combos 원본 | SearchConditionFieldConfig 필드 |
|------------------------|--------------------------------|
| combo ID | `id` (camelCase) |
| combo 라벨 (Static text 참조) | `label` |
| combo dataset | `dataSource` (useState 변수) |
| combo displayMemberPath | `dataPathToText` (camelCase) |
| combo selectedValuePath | `dataPathToValue` (camelCase) |
| - | `type: 'combo'` |
| - | `required: false` |

### 8.2 SearchConditionValues → SearchParams 변환

```ts
const params: {화면명}SearchParams = {
  codeType: typeof searchFilters.codeType === 'string' ? searchFilters.codeType : null,
  useStatus: typeof searchFilters.useStatus === 'string' ? searchFilters.useStatus : null,
};
```

각 조회조건 필드에 대해 string 타입 검사 후 null fallback.

## 9. gfn_Transaction → API 함수 매핑

| strSvcId / 용도 | 변환 함수명 | 반환 타입 |
|------------------|-------------|-----------|
| search (메인 조회) | `fetch{화면명}s` | `ApiResponse<{화면명}Row[]>` |
| save (메인 저장) | `save{화면명}s` | `ApiResponse<{화면명}Row>` |
| 보조 조회 (codeType 등) | `fetch{DsTypeName}` | `ApiResponse<{DsType}[]>` |

**규칙:**
- `strOutDatasets`만 있고 `strInDatasets` 없음 → 조회 함수
- `strInDatasets` 있음 → 저장 함수
- 메인 Dataset: 화면명 기반 함수명 + 복수형 `s`
- 보조 Dataset: `fetch` + 타입명
